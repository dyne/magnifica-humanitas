# Production reading verification

L6.1, 14 October 2026. Tested working tree on `feat/interactive-reading`,
starting at `b24956b82640bae9018abca6febe5f1e0b2461cb`. This report covers local
production previews, not a published release or a reader study.

## Reproduce

```sh
npm ci --cache /tmp/mh-npm-cache
npm run check
npm run source:check
PLAYWRIGHT_BROWSERS_PATH=/tmp/mh-l2-browsers \
  BROWSER_EVIDENCE_DIR=output/playwright/l6/hosting npm run test:browser:all
```

Install the matching Playwright Chromium binary first if that browser directory
does not exist. `npm run test:browser:all` builds and tests `/` and
`/magnifica-humanitas/` sequentially, retaining separate reports and build hashes.
Do not run another build concurrently with this command.

Environment: Linux 6.12.111+deb13-amd64 x86_64, Node 24.21.0, npm 12.2.0,
Playwright 1.64.0, headless Chromium 156.0.8078.4, axe-core 4.11.0.

## Accessibility and finish review

Bounded Impeccable audit and polish performed by the assigned executor; no
independent design-review agent or usability participant was used. Mechanical
detector: zero findings. Audit judgments: accessibility 3/4, performance 3/4,
responsive 4/4, theming 4/4, implementation integrity 4/4 (18/20). These are
review judgments, not certification scores. Product-specific question regions,
explicit source/interpretation labels and finite endings retain the Read mode.

Axe scans all 13 surfaces in both themes at each base: **52 scans**, zero
violations and zero incomplete results under the configured WCAG A/AA through
2.2 and best-practice rules. Raw results: `{root,subpath}/accessibility.json`.
Automated scanning cannot establish complete WCAG conformance.

Manual source/DOM review checked heading/landmark order, native links versus
buttons, input names, polite status messages, hidden SVG with equivalent HTML
links, and source quotation/paraphrase/interpretation labels. Existing browser
journeys verify keyboard skip, route heading focus, invoking-link focus and
scroll on Back/Forward, optional reflection focus, save/remove/Undo, refresh,
invalid links, search recovery and storage denial/quota/corruption/version
handling. Reduced motion is enabled for the full new screenshot matrix;
existing tests also assert no running animations during reflection.

There is no custom menu or modal dialog: navigation remains visible; clear-all
confirmation is inline with Confirm/Cancel controls and tested focus return.
No modal trapping or menu Escape behavior is claimed. Screen-reader output
with NVDA/VoiceOver and physical touch devices has **not** been tested;
accessibility-tree/manual semantics checks do not substitute for those checks.
Firefox, WebKit, browser zoom and user stylesheet variations remain unmeasured.

The only product correction from this review was outdated About text that
claimed four concepts, one trail and future saved places. It now describes the
complete corpus and actual persistent/temporary local state; a browser assertion
protects that correction. No unresolved P0/P1 was found in the inspected scope.

## Performance sample

One sample per hosting base, cold browser context, 390×844, local Vite preview.
Chrome DevTools throttling: 150 ms latency, 200,000 bytes/s download,
100,000 bytes/s upload, 4× CPU slowdown. No field dataset, real mobile radio,
deployment compression or cross-device benchmark is implied.

| Measurement | Root | Project subpath |
| --- | --- | --- |
| Initial JS, Node gzip bytes | 88,427 | 88,435 |
| First contentful paint, ms | 920 | 936 |
| Entry long task, ms | 113 | 130 |
| Maximum long task including lazy reading/context, ms | 151 | 155 |

Exact timings vary on repeat runs; authoritative samples are in
`output/playwright/l6/{root,subpath}/performance.json`. The reproducible budget
assertion is initial JS ≤153,600 bytes gzip. Initial entry requests exclude
the deferred reading sequence and reviewed context chunks. Delaying the sequence
by 1.2 seconds exposes a visible polite loading message, then all 245 entries
render; source context remains usable under network throttling. Existing tests
verify deferred-chunk failure, retry and original-source access.

The small number of >50 ms tasks under 4× CPU slowdown is a retained P2
performance observation: rendering the complete adaptation can briefly delay
input. No task blocks a reading journey in these checks. Consider measuring on
physical lower-end devices before changing rendering; preserve all source-order
content and navigation. No reader study, comprehension gain, learning efficacy,
published deployment or comprehensive accessibility claim is made.
